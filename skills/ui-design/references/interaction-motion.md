# Interaction and motion

Choose motion from the brief, not a house style. A fashion launch can be theatrical; a dispatch tool may need fast, legible feedback; a playful product can invite exploration. Expressive atmosphere and delight are legitimate goals alongside orientation and feedback. Agree the intensity with the user's intent, existing brand and actual content. Do not replace a requested effect with a static page or a hover-only flourish.

These are techniques to adapt, not a required effects checklist. Combine them when appropriate, including richer sequences for a brief that asks for them. Prototype the actual gesture, states and visual treatment rather than assuming that naming a library implements a result.

| Technique and fit | Construction and states | Verify |
| --- | --- | --- |
| Responsive icons, press and release: controls, reactions, navigation | Animate transforms, opacity or compatible SVG shapes from the real control state; expose a correct accessible label and pressed/expanded state. Design idle, focus, pressed, disabled and return states. | Keyboard and touch activation, repeated taps, cancellation, final state and reduced motion. |
| Spatial depth, sticky stories and parallax: campaigns, portfolios, editorial | Give layers different scroll-linked movement only where the story benefits; retain readable content and a normal-flow fallback. Feature-detect scroll timelines; on small screens adjust or remove independent layer travel where it would cover text. | Watch the entire scroll at phone, intermediate and desktop widths. Measure moving layers against text, inspect slow scroll and motion off; unsupported browsers must still show the content. |
| Shared-element and card-to-detail transitions: collections, product detail, media | Use matching geometry or the View Transition API as progressive enhancement. Update the real view even if an animation is skipped; move focus appropriately when its previous target disappears. | Navigate in and back, click rapidly, use keyboard, check unsupported browsers and reduced motion. Avoid stretched text and duplicate transition names. |
| Tilt, pointer spotlight, glowing edges: tactile product or campaign surfaces | Keep the hit target stable and animate an inner decorative layer. Clamp pointer coordinates, reset on leave/cancel and offer a still appearance on touch and keyboard. | Pointer entry/exit, fast movement, focus, touch, contrast and small viewports. Check that the highlight never conceals a label. |
| Glass, ambient color and dimensional scenes: brand atmosphere, immersive products | Compose layered translucent surfaces with a tested opaque fallback; extract colors only from real, permitted assets if the design calls for it. For WebGL/3D use an actual interactive scene, lazy loading and a fallback, and pause unnecessary work offscreen or when hidden. | Contrast over all changing backgrounds, reduced motion, unsupported effects, device performance and missing media or WebGL. Do not imply a demo uses a 3D engine or live data when it does not. |
| Drag, hold, swipe, radial actions and before/after: direct manipulation | Model begin, move, commit and cancellation explicitly; use pointer capture when appropriate, handle `pointercancel` and preserve page scrolling. Provide a visible button or keyboard alternative; a hold must not silently trigger an unrelated action. | Touch, mouse, keyboard, interrupted gestures, out-of-bounds release, repeated actions and recovery. |
| Reordering, expanding cards and data transitions: boards, filters, charts | Animate between measured previous and next positions or use layout transitions. A single real state must determine ordering, chart, label and totals; animation never delays correctness or invents progress. | Fast successive changes, empty states, interrupted animations, final values, reduced motion and consistent visible data. |
| Drawers and dialogs: navigation and focused tasks | Animate the surface with a clear opening/closing state and a robust immediate fallback. Preserve semantic dialog behavior, focus placement and return, Escape and scrolling. | Open/close by mouse, touch and keyboard, cancel mid-transition, return focus, and test content longer than the viewport. |

## From an idea to a working sequence

- **Scroll:** distinguish an entrance triggered once from a scene whose progress follows scroll position. For a scrubbed scene, define the start/end geometry and which layers move at which rates; use a named view timeline when supported or a bounded, passive measured fallback when necessary. Keep text and the hit targets independent of moving decoration. Check every section of the journey in both scroll directions, not only the first and final frame.
- **Direct manipulation:** preserve the pointer's initial grab offset, calculate the position from actual bounds, and decide whether release commits, snaps back, or cancels. For inertial gestures, estimate recent velocity and pass an appropriate initial velocity into the settling animation; don't copy fixed thresholds between different controls. Handle capture loss, interruption and touch scrolling. A range input can supply a keyboard and touch-accessible comparison slider without custom drag physics.
- **Morph and continuity:** identify which visible object persists between states, measure its starting and ending geometry and let the real DOM update even if animation fails. Repeated actions can interrupt or retarget the effect; a detail view still needs an accessible close/back path and correct focus. A smooth visual alone does not make a nonfunctional control complete.
- **Material and atmosphere:** choose the moving layer, light source, depth and palette from the actual art direction. Plan an opaque and still state first; if sampling a cover or using WebGL, the source and availability must be real. Test bright/dark source material and a slower device; a blur, color change or 3D scene is allowed to be the expressive point when the brief calls for it.
- **Sequencing:** map user action, state change, visual response and completion to a single timeline. Keep frequent controls responsive, vary duration to distance and context, and let animation stop or redirect on repeated input. Loading and progress must reflect real work; do not fabricate a delay merely to show a transition.

Treat `prefers-reduced-motion` as a preference that changes the choreography; make important content and actions available without movement. If offering a motion switch, its label and actual behavior must agree, including initial system preference and later changes. Avoid forcing animation on users who have paused it. Test real frames and interactions, not only a static screenshot or a passing DOM check. Label simulated experiences honestly. When using third-party code or media, check the actual license and retain required notices.

For implementation details and compatibility, consult the current [View Transition API](https://developer.mozilla.org/en-US/docs/Web/API/Document/startViewTransition), [scroll-driven timelines](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Scroll-driven_animations/Timelines), and [pointer capture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture) documentation. A technique's inclusion here is not evidence that every source implementation or original video has been inspected.
